# excel-master Darwin 优化设计

## 目标

优先优化 `SKILL.md` 的执行可靠性，不改变核心 Excel 生成功能、公开脚本接口或依赖。真实提示测试若暴露自包含辅助脚本的共同根因，可以追加最小修复和回归测试。优化必须经过真实提示测试和独立盲评；分数没有严格提高时恢复修改前版本。

## 方案比较

### 方案 A：只追加缺失章节

在现有文件末尾追加执行步骤、失败处理和黑名单。

- 优点：改动小，不容易遗漏现有知识。
- 缺点：现有文件已经较长，继续追加会造成重复，整体架构分可能下降。
- 可逆性：高。

### 方案 B：结构化压缩（采用）

把现有内容重组为“入口判断 → 安全准备 → 选择脚本 → 执行 → 验证 → 交付”，加入三段式失败处理表、显性检查点和反例黑名单；保留主题表、关键安全规则与资源索引，删除重复的历史修复叙述。

- 优点：同时改善工作流、失败模式、检查点、具体性和整体架构，且能缩短文件。
- 缺点：需要逐项核对，防止删掉有效业务规则。
- 可逆性：高，修改前有集中备份和哈希。

### 方案 C：从零重写

完全丢弃现有结构，重新写一份短技能说明。

- 优点：最容易得到整齐结构。
- 缺点：容易遗漏主题、公式保护、条件格式和复杂区块边界；细粒度 LLM 评分不足以证明重写更好。
- 可逆性：高，但验证成本最高。

## 推荐理由

采用方案 B。它直接针对当前静态证据：0 个编号工作流标题、0 个显性检查点、0 个三段式失败表、0 个黑名单章节，同时避免方案 A 的继续膨胀和方案 C 的信息丢失风险。

## 目标结构

1. 触发条件与能力边界。
2. 依赖与自包含约束。
3. 六步执行工作流，每步写明输入、动作和输出。
4. 两个显性检查点：
   - 修改已有文件或解释复杂布局前确认范围与备份。
   - 交付前必须完成值、公式和格式验证。
5. 三段式失败处理表：触发条件、一线处理、仍失败兜底。
6. 反例黑名单：禁止猜测复杂区块、禁止重写公式、禁止静默改条件格式、禁止结束全部 Excel 进程、禁止未验证即交付。
7. 参数速查、主题表和资源索引。

## 数据流

```text
用户请求
  → 判断任务类型
  → 获取输入文件和明确参数
  → 建立集中备份
  → 调用本目录对应脚本
  → 验证值、公式、格式及输出文件
  → 报告路径、证据和限制
```

## 错误处理

- 输入不存在：停止，不加载可选依赖，重新通过文件选择窗口取得输入。
- 复杂布局不明确：不猜测，要求明确矩形区块。
- Excel COM 或剪贴板失败：真实截图先取消复制模式，释放工作表、区域、形状集合和工作簿等 COM 代理，再退出独立 Excel 实例；打码定位改用已有的 openpyxl，不再创建第二个 Excel 实例。
- 敏感列定位：截图和打码强制使用相同的工作表及显式范围，避免非活动工作表下打码错列。
- PNG 输出已存在：先复制到统一 BackUp 目录并校验，再允许覆盖。
- 备份校验失败：停止修改，保留原文件。
- 公式、值或条件格式验证不一致：不交付输出，恢复备份并报告差异。

## 测试策略

- 静态：Darwin 九维评分、runtime 红灯扫描、资源路径检查、技能元数据校验。
- 效果：3 条测试提示分别由无技能实例和带技能实例完整执行。
- 盲评：至少 2 个独立 judge 对随机标签的改前/改后版本评分。
- 回归：先用失败测试锁定 COM 清理顺序、工作表一致性和 PNG 覆盖备份，再运行完整测试，并复核真实截图、打码输出、隐藏进程退出和既有 Excel 共存。

## 迁移与回滚

- 不创建提交或分支，避免混入当前工作树的上一轮本地改动。
- 修改前把 `SKILL.md` 和本轮触及的辅助脚本、测试、设计及计划复制到集中备份目录并校验 SHA256。
- 若优化后评分不升、judge 无一致偏好或回归失败，使用备份通过局部补丁恢复。

## 自审

- 无待定项和占位符。
- 说明文本仍是主要优化资产；辅助脚本只修复实测暴露的 COM 释放共同根因，不扩展 Excel 功能。
- 与自包含约束、用户预授权和现有测试策略一致。
