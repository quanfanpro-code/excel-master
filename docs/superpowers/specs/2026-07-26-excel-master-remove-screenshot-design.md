# excel-master 移除截图功能设计

## 目标

完整移除真实 Excel 截图和敏感列打码分支，使当前技能说明、运行脚本、测试与依赖保持一致，同时不改动 Excel 生成、美化和复杂区块的核心实现。

## 方案比较

### 方案 A：只隐藏入口

从 `SKILL.md` 和 `README.md` 隐藏截图说明，但保留脚本、测试和依赖。

- 优点：改动最少。
- 缺点：死代码、可选依赖和维护成本仍在，用户仍可能从脚本或测试发现并调用。
- 结论：不采用。

### 方案 B：完整移除活动分支，保留历史记录（采用）

删除运行脚本、专用参考文档、专用测试、测试提示和活动说明；历史审计与结果日志保留，并明确记录功能已移除。

- 优点：满足 YAGNI，当前能力与依赖一致；核心调用链不变；历史仍可审计。
- 缺点：测试数量减少，但减少的全部是被删除功能的专用测试。
- 可逆性：高，删除进入回收站且有集中备份。

### 方案 C：同时清除全部历史痕迹

除活动分支外，再删除历史评估文档、结果记录和验证图片。

- 优点：全局搜索不到截图术语。
- 缺点：破坏审计链，删除范围大且没有功能收益。
- 结论：不采用。

## 设计边界

保留的三个运行入口：

1. `scripts\make_excel.py generate`
2. `scripts\make_excel.py beautify`
3. `scripts\format_excel_sections.py`

删除的活动分支：

1. `scripts\excel_camera_screenshot.py`
2. `scripts\blur-excel-column.py`
3. `references\excel-screenshot-camera.md`
4. 仅服务于上述分支的测试、测试提示、说明和缓存。

## 依赖设计

当前运行依赖收敛为：

```text
pandas
openpyxl>=3.0
```

技能不再声明 pywin32、Pillow、Microsoft Excel COM 或系统剪贴板。系统中已有包不做卸载，避免影响其他项目。

## 删除与恢复

1. 解析并核对每个目标的绝对路径，确保都位于 `excel-master` 目录。
2. 把所有待修改和待删除文件复制到 `C:\Users\27651\BackUp\excel-master_时间戳\`，保留相对路径。
3. 比较源文件与备份 SHA256，任一不一致即停止。
4. 修改活动文件后，通过 Windows 原生回收站接口逐文件删除目标。
5. 验证目标不再存在；如需恢复，优先从集中备份取回。
