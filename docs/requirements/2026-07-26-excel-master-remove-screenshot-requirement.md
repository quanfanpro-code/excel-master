# excel-master 移除截图功能需求

## 背景与问题

`excel-master` 当前包含“真实 Excel 截图”和“敏感列打码”两项可选能力。用户确认这些能力没有实际价值，要求完整删除，同时不得影响 Excel 生成、美化、复杂区块、公式保护、条件格式和主题功能。

## 用户目标

- 删除真实 Excel 截图及敏感列打码的运行脚本、活动说明、测试和可选依赖声明。
- 保持本地技能自包含；核心功能只依赖本技能目录内资源及 `pandas`、`openpyxl`。
- 删除必须可恢复；修改前建立集中备份并校验。
- 用户已明确授权自主确定删除范围，无需再次等待确认。

## 功能范围

- 删除截图脚本、打码脚本和截图专用参考文档。
- 删除截图与打码测试及测试提示。
- 清理 `SKILL.md`、`README.md`、实施检查表和技能卡中的活动入口、依赖、失败处理与交付说明。
- 通过 Windows 回收站删除明确列出的文件和对应的陈旧字节码缓存。
- 保留既有历史审计、Darwin 评估和结果日志中的历史记录，并新增“功能已移除”记录。
- 回归验证 Excel 生成、美化和复杂区块三个保留入口。

## 明确不做

- 不卸载系统中已经安装的 pywin32 或 Pillow。
- 不修改 `make_excel.py`、`format_excel_sections.py` 的公开接口和业务逻辑。
- 不删除历史报告、历史验证图片或集中备份。
- 不启动或结束任何用户 Excel 进程。
- 不提交、不推送、不创建 PR。

## 约束与风险

- 当前工作树包含上一轮未提交改动，不能使用 reset、stash、revert 或整文件恢复破坏现状。
- 所有已有文件修改前必须备份到 `C:\Users\27651\BackUp\` 的独立时间戳目录并校验 SHA256。
- 文件删除只能进入 Windows 回收站，不能永久删除。
- `SKILL.md` 保持无 BOM UTF-8 和 CRLF；其他新增中文文本使用 UTF-8 BOM 和 CRLF。
- 历史文档会继续出现截图术语，但不得再作为当前入口或运行依赖。

## 验收标准

1. `scripts\excel_camera_screenshot.py`、`scripts\blur-excel-column.py` 和 `references\excel-screenshot-camera.md` 不再存在于活动技能目录。
2. `SKILL.md`、`README.md`、活动检查表、测试提示、活动测试和技能卡不再提供截图或打码能力。
3. 活动运行路径不再声明 pywin32、Pillow、Excel COM 或剪贴板依赖。
4. 保留的全部测试通过；删除截图专用测试后预计为 12 项。
5. 生成、美化和复杂区块真实样例均成功，值、公式和条件格式保持不变。
6. `quick_validate.py`、runtime 红灯、直接资源引用、自包含和中文编码检查全部通过。
7. 待删除文件均有集中备份且哈希一致，并通过 Windows 回收站删除。
8. 没有启动、结束或干扰用户 Excel 进程。

## 调研结论

- 两个截图相关脚本只有技能说明、参考文档和专用测试调用，`make_excel.py` 与 `format_excel_sections.py` 均不依赖它们。
- 删除截图分支不会改变三个核心入口的调用链。
- 只隐藏入口会留下死代码和可选依赖，不能满足“删除”和“自包含”的目标。

## 已确认假设

- “删除”包括运行代码、活动说明、专用测试、测试提示和生成缓存。
- 历史报告属于审计证据，保留比清除更安全；其中的截图描述只表示过去状态。
- 用户要求“自己看着办”，因此所有 requirement-workflow 检查点按上述验收标准自动推进。
