# excel-master Darwin 优化需求

## 背景与问题

`excel-master` 已完成作者版与本地版合并，代码和真实 Excel 样例均已通过验证。本轮不新增功能，只用 Darwin Skill 2.0 评估并优化技能说明，使 agent 更稳定地选择正确入口、处理失败并避开危险动作。

## 用户与使用场景

- 用户：在 Windows 环境使用 WorkBuddy/Codex 处理 Excel 的非技术用户。
- 典型场景：从 CSV 生成报表、美化含公式和条件格式的工作簿、处理多数据块、生成真实截图并打码。

## 功能范围

- 按 Darwin 九维 rubric 建立基线和优化后评分。
- 使用 3 个真实测试提示对比“无技能基线”和“带技能执行”。
- 每轮只修改 `SKILL.md`，不改 Python 脚本、参考资料或核心功能。
- 增加清晰工作流、失败分支、显性检查点和反例黑名单时，优先复用现有内容并删除重复。
- 生成 `test-prompts.json`、`results.tsv`、需求、设计、计划和复核记录。

## 明确不做

- 不新增 Excel 功能、依赖、主题或脚本。
- 不提交、不推送、不创建 PR。
- 不删除文件或清理既有缓存目录。
- 不把本技能绑定到单一 agent runtime。

## 约束与风险

- 当前 Git 工作树包含上一轮尚未提交的本地改动，不能用提交、stash、reset 或 revert 破坏它们。
- Darwin 的棘轮改用集中备份、SHA256 和盲评结果实现。
- `SKILL.md` 必须保持可被技能校验器识别，因此使用无 BOM UTF-8；其他新增中文文件使用 UTF-8 BOM。
- 优化后 `SKILL.md` 不得超过原文件大小的 150%，并优先缩短。

## 验收标准

1. Runtime 红灯扫描为 0。
2. `quick_validate.py` 通过。
3. 原有 16 项代码测试全部通过。
4. 3 个测试提示至少完成 1 次完整对照实测，`dry_run` 比例不超过 30%。
5. 至少 2 个独立盲评 judge 对优化版形成一致偏好；若没有一致偏好则恢复备份。
6. Darwin 加权总分严格高于基线，且没有维度明显下降。
7. 公式、值、条件格式、复杂区块、真实截图和打码能力的既有验证保持通过。

## 调研摘要

- Darwin 本地规则显示，现有技能最可能的短板是工作流清晰度、失败模式编码、显性检查点和风险黑名单。
- 当前 Runtime 红灯扫描命中 0 项。
- 当前 `SKILL.md` 有大量能力说明和历史坑点，但缺少单一线性执行流程、三段式失败处理表和独立反例章节。
- 当前工作树非干净状态，因此采用文件级棘轮，不执行 Git 写操作。

## 已确认假设

- 用户已预先授权本对话中完成评估、备份、优化和独立评审，无需在中途检查点停下。
- 优化目标是提高 agent 执行可靠性，不追求增加篇幅或为了评分堆叠规则。

## 待确认项

无。用户授权按推荐方案完成后统一汇报。
